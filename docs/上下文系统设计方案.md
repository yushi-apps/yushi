# 上下文系统设计方案

## 目标

基于可逆计算原理，设计一个结构化的，可演化的上下文系统，解决有限上下文窗口中有效管理无限增长的交互历史问题，构建一个自适应、可演化的“Claw”。

## 核心概念

### 记忆（Memory）
记忆是Agent的一切，每一份记忆都是一个差量，所有记忆差量的组合就是Agent。部分记忆差量的组合形成经验成为技能。记忆定义如下：
``` xml
<Memory id="string" created-at="!long">

    <system-prompt xdef:value="string" />

    <available-skills>
        <skill name="string" description="string" />
    </available-skills>

    <available-tools>
        <tool name="string" description="string" input-schema="json" />
    </available-tools>

    <available-agents>
        <agent name="string" description="string" />
    </available-agents>

    <user-intent xdef:value="string" />

    <current-progress>
        <todolist>
            <todo id="int"  content="string" status="enum::done, ongoing, waiting" />
        </todolist>

        <available-files>
            <file name="string" description="string" />
        </available-files>

        <rule />

        <next-n-steps>
            <step id="int" description="string" />
        </next-n-steps>
    </current-progress>
    
    <!-- 三种 Action 类型直接作为 Memory 的顶级元素，通过 x:extends 链式继承逐步累积 -->
    <thought id="int" content="string" />
    <toolcall id="int" name="string" arguments="json" status="enum::success, failed" result="string" error="string" />
    <summary id="int" begin_action="int" end_action="int" content="string" />

</Memory>

```

### 动作（Action）
Action 表示一次工具调用、摘要生成或 LLM 思考。三种 Action 类型（`thought`、`toolcall`、`summary`）直接作为 Memory 的顶级元素存在，通过差量文件的 x:extends 链式继承逐步累积：
``` xml
<!-- thought: LLM 的思考过程 -->
<thought id="int" content="string" />

<!-- toolcall: 工具调用及其结果 -->
<toolcall id="int" name="string" arguments="json" status="enum::success, failed" result="string" error="string" />

<!-- summary: 历史动作的摘要 -->
<summary id="int" begin_action="int" end_action="int" content="string" />
```

**注意**：`<history-actions>` 不是 Memory XML 的结构节点，而是 `get_history_actions_xml()` 函数程序化构造的**过滤视图**——从合并后的 Memory 中筛选 `toolcall` 和 `summary`（排除 `thought`），仅供 Schedule Agent 等特定场景内部使用。

### 记忆差量
记忆差量是一个遵循Memory.xdef格式的XML文件，可以使用x:extends属性，继承自某个记忆差量，使用x:override属性，执行合并、删除、追加等操作。
记忆差量文件的命名规则为ID_TYPE.xml，其中ID为递增的整数，TYPE为workspace, intent, thought, toolcall, summary。

- workspace保存APP的system-prompt、可用技能、可用工具、可用Agent等信息，自动继承上一个workspace文件。
- intent保存用户输入的意图，会自动继承上一个记忆差量和workspace文件。
- thought保存LLM的思考，会自动继承上一个记忆差量和workspace文件。
- toolcall保存工具调用结果，会自动继承上一个记忆差量文件和workspace文件。

## 执行流程

### APP启动
APP第一次启动时会获取以下内容到Registry中，同时保存到workspace文件中:
- 从YUSHI.md中读取内容保存到<system_prompt>
- 从注册的工具列表中获取工具名和描述保存到<avaliable-tools>
- 遍历`skills`目录获取技能名称和描述保存到<avaliable-skills>
- 遍历`agents`目录获取Agent名称和描述保存到<avaliable-agents>

当对应信息有更改时，会自动更新Registry，同时自动创建一个新的workspace文件，自动继承上一个workspace文件。

### 用户输入
用户输入会保存为一个Memory文件，命名为ID_intent.xml

### LLM 请求构建

采用**两通道设计**，将结构化上下文与对话历史分离：

**System Prompt 构成**（结构化上下文通道）：
1. 第一部分：YUSHI.md 的完整内容（Agent 的基础 prompt）
2. 第二部分：结构化 Memory XML，仅包含以下元素：
   - `system-prompt`
   - `available-tools`、`available-skills`、`available-agents`
   - `user-intent`
   - `current-progress`
   - **不包含 action 历史**（`thought`、`toolcall`、`summary`）

**Messages 数组**（对话历史通道）：
从 `history/` 差量文件动态重建的标准 OpenAI 消息链：
- `intent` 差量文件 → `User` 消息
- `thought` + 后续 `toolcall` → `Assistant`（含 `tool_calls`）+ `Tool`（结果）成对出现
- `thought`（无后续 `toolcall`）→ 纯文本 `Assistant` 消息
- `assistant(tool_calls)` → `tool(result)` 始终成对出现，满足 OpenAI API 约束
- `toolcall` 差量文件包含 `tool-call-id` 属性，用于消息配对

**请求构建流程**：
```
用户输入 → chat_stream()
  → memory::init() 创建 0_workspace.xml
  → memory::create_intent_delta() 创建 N_intent.xml
  → query() 函数：
    → memory::build_messages_from_history() 从差量文件重建消息链
    → query_llm():
      system_prompt = YUSHI.md + 结构化 Memory XML（不含 action 历史）
      messages = 从 history 差量文件动态重建的标准消息链
    → LLM 返回 AssistantMessage（可能含 tool_uses）
    → 保存 thought delta
    → 执行工具 → 保存 toolcall delta（含 tool-call-id）到 Memory
    → 递归 query() ← 每次从 history 重新重建消息
    → 直到 LLM 不再调用工具
```

### 工具执行
工具执行时，在 Action 列表中保存工具执行结果。`toolcall` 差量文件包含 `tool-call-id` 属性，用于与 `Assistant` 消息中的 `tool_calls` 配对：
``` xml
<toolcall id="int" tool-call-id="string" name="string" arguments="json" 
          status="enum::success, failed" result="string" error="string" />
```
工具执行结果通过 `toolcall` 差量文件保存到 `history/` 目录，在消息链重建时通过 `tool-call-id` 与对应的 `Assistant` 消息配对，生成符合 OpenAI API 约束的 `Tool` 消息。
每个 Action 以 `ID_toolcall.xml` 保存，使用 `x:extends` 属性继承自上一个记忆差量文件和 workspace 文件。

### 计划思考
当 action 数量超过 10 条时，Schedule Agent 会进行进度规划。此时通过 `get_history_actions_xml()` 函数从 Memory 中筛选 `toolcall` 和 `summary`（排除 `thought`）构造 `<history-actions>` 过滤视图，仅供 Schedule Agent 内部使用。Schedule Agent 按照 `<current-progress>` 格式输出相关信息。Schedule Agent 的 prompt 定义如下：

``` markdown
你是上下文管理专家。根据历史动作，输出简洁的摘要和下一步规划。

历史动作将在 10 步后被舍弃，你需要在 `<rule>` 中保留后续需要的关键信息。

## 输出格式

```xml
<current-progress>
    <todolist>
        <todo id="1" content="任务描述" status="done|ongoing|waiting" />
    </todolist>
    <available-files>
        <file name="文件路径" description="用途说明" />
    </available-files>
    <rule>
后续需要保留的信息：关键结论、失败次数、格式样例等
    </rule>
    <next-n-steps>
        <step id="1" description="具体工具操作" />
    </next-n-steps>
</current-progress>
```

## 要求

1. 直接输出 XML，不要包含解释
2. todo 状态：done（已完成）、ongoing（进行中）、waiting（待处理）
3. next-n-steps 每步必须是具体工具操作，最多 10 步
4. 任务完成时，next-n-steps 只需一步说明完成
5. 如果正在执行 skill，第一步应重新读取 skill.md
```
